🔬 Hypothesis Evaluation

Your team's hypothesis: "Many of the examples and tutorials are too long."

Verdict

Partially confirmed — with an important distinction. The hypothesis holds strongly for tutorials (avg 22 screens, 29 of 29 exceed 8 screens), but examples are appropriately concise (avg 3.4 screens). The length problem is concentrated in the Introduction to p5.js tutorial series and three specific outlier tutorials that exceed 10 screens each.

High Priority

Split the 3 critical tutorials

Creating & Styling HTML (12.3), p5.strands: Shaders (11.1), and Repeating with Loops (10.5) are extreme outliers. Each should be split into 2–3 focused sub-tutorials.

High Priority

Shorten the core Introduction series

The 8-tutorial Intro to p5.js series averages 8.2 screens — well above a comfortable reading length. Variables & Change (9.7), Organizing Functions (8.9), and Animating with Media (8.0) need trimming or chunking.

Medium Priority

Add progress indicators to long tutorials

For tutorials 6+ screens long, add a visible scroll-progress bar and section jump-links so users can navigate without scrolling the full page.

Medium Priority

Surface example code in static HTML

Example sketch code loads dynamically via Astro islands — it's invisible to screen readers, scrapers, and search engines. Consider adding a "View Code" static code block alongside each live embed.

Lower Priority

Examples are appropriately short

The examples section does not have a length problem. Avg 1.3 screens is appropriate for demo pages. Focus usability investment on tutorials instead.

Lower Priority

Critical AI series: check engagement drop-off

The 4-part Critical AI series averages 6.5 screens with heavy prose. These pages likely serve a narrow audience — consider whether the depth matches user intent.

🖊 Core Drawing & Shapes ~18 pages

🖱 Animation & Interactivity ~22 pages

Variables, conditionals, loops, mouse/keyboard events, frameCount, draw loop control. The largest theme cluster spanning the entire Introduction to p5.js tutorial sequence.

🌐 3D Graphics & WebGL ~20 pages

3D geometry, lighting models, materials, GLSL shaders, framebuffers, GPU optimization. Covered across 6 WebGL tutorials and 7 examples sub-categories (3D, Advanced Canvas Rendering).

🖼 Media & Data I/O ~18 pages

🤖 AI & Critical Technology ~4 pages

Generative AI, LLM coding assistants, prompt engineering, bias, sentiment analysis, no-code chatbots. A new 4-part Critical AI tutorial series — unique content not found in many creative coding resources.

🔬 Methodology & Notes

How data was collected, how screen counts were estimated, and known limitations.

Screen Count Formula

Estimated rendered height using:
screens = ((paragraphs × 120) + (code_lines × 18) + (headings × 40) + 200) / 950

Where 950px = standard screen height at 1440px width. Paragraph height (120px) assumes ~5 lines at 24px line height. Code line height (18px) reflects monospace editor rendering. Heading height (40px) covers h2/h3 with margin.

Data Collection

Pages were fetched via HTTP in parallel batches using the WebFetch tool. For each page, the static HTML was parsed for:

  • Heading counts (h1–h4 in main content)
  • Paragraph counts (<p> in body)
  • Code block lines (<pre> / <code> elements)
  • Visible word count (body text)
  • External and internal links (href values)

Example Pages — Important Caveat

The beta.p5js.org site uses Astro island hydration. Example pages render their p5.js sketch code via dynamic JavaScript components — the sketch source code is not present in the static HTML served to the fetcher.

This means: (1) screen counts for examples only reflect the description text, not the live sketch embed, and (2) p5.js function lists for examples were inferred from page descriptions and canonical repository knowledge.

Tutorial Pages — High Confidence

Tutorial pages are fully rendered as static Markdown-to-HTML. All text, headings, code blocks, and links are present in the static HTML and were accurately scraped. Screen count estimates for tutorials are the most reliable data in this report.

Estimated vs. Scraped

10 of 91 pages are marked Estimated in the data table. These are the Imported Media (audio/video) and Input Elements / Transformation examples from batch 2, where the scraping agent did not complete. Values are estimated from patterns observed across the remaining 81 pages. All other pages are marked Scraped.

Limitations

  • Live sketch embed height (~400–600px, ~0.5 screens) is not captured by formula — actual example pages are slightly taller than reported
  • Dynamic content (interactive sliders, expandable sections) not measured
  • Mobile viewport not analyzed — report uses 1440×950 only
  • Images estimated at 0 height — pages with many screenshots may be taller
